# ADR 0009 — Skeleton as the enforced composition boundary

Status: Accepted

## Decision

Extend the existing durable `CREATIVE_ANALYSIS` job through a separate `SKELETON` generation run. Creative DNA completion advances the creative to `SKELETONIZING`; only atomic Skeleton completion advances it to `READY` and marks the job successful. Retries infer their resume stage from existing transcript and deconstruction artifacts, avoiding repeated upstream provider work.

Generate one structured extraction containing a canonical `Skeleton` plus source-derived restricted elements. Validate the Skeleton against `schemas/skeleton.schema.json`, validate restricted elements against `schemas/restricted_elements.schema.json`, and reject the whole extraction if any normalized restricted value appears anywhere in the Skeleton payload. The provider receives the corresponding strict composed schema through the existing Model Gateway.

Persist abstract Skeleton data and restricted source values in separate tenant-owned tables. Authenticated tenant members, including VIEWER, may read the abstract Skeleton. The restricted-element table has RLS enabled but no authenticated policy or grant; it is service-only and is not returned by the Skeleton API or UI. Its eventual application read path is reserved for Originality evaluation, not Composer.

The extraction prompt may receive the raw transcript only inside the Skeleton extraction workflow. It treats the transcript as delimited untrusted data and requires names, claims, facts, phrases, metaphors, events, settings, and scenes to become either abstract functions or isolated restricted values. `avoid_copying` contains abstract categories rather than source wording. No embedding column or model is introduced until the post-MVP embedding milestone.

## Rationale

- The database and API split makes the Originality Firewall a system boundary rather than a prompt disclaimer.
- Finishing the job only after Skeleton persistence makes `READY` mean the complete Milestone 5 analysis contract is available.
- A single extraction call can reason jointly about safe abstraction and restricted material while atomic persistence prevents partial boundary state.
- Exact normalized collision rejection provides a deterministic minimum safety check before later fuzzy and semantic Originality Guardian checks.
- Resume-stage inference keeps durable retries honest, observable, and cost-aware.

## Consequences

- Future Composer repositories and context builders must depend on `skeletons` and Brand Brain only; they must not query transcripts, deconstructions, or restricted elements.
- Future Originality evaluation may receive restricted elements through a narrowly scoped service repository.
- Exact collision checks do not prove that every close paraphrase is safe. Milestone 7 adds fuzzy and semantic evaluation; Milestone 5 gold fixtures establish the required source-specific removal baseline.
- Restricted values are intentionally absent from customer-facing Skeleton responses even though the product stores them for safety evaluation.
