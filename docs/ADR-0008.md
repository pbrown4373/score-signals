# ADR 0008 — Schema-validated analysis and complete generation lineage

Status: Accepted

## Decision

Run transcription and Creative DNA generation as one durable `CREATIVE_ANALYSIS` job after media preprocessing. Record transcription as a first-class `TRANSCRIPTION` generation run even though the original logical enum omitted it, because the repository contract requires lineage for every completed AI artifact. A retry reuses a validated transcript and resumes Creative DNA generation without re-transcribing.

Persist transcript and Creative DNA outputs only after application-side validation against versioned JSON Schemas. The canonical Creative DNA schema remains the persistence contract. For the OpenAI Structured Outputs request, derive a strict provider projection that makes every object property required while preserving nullable optional values; this avoids weakening or rewriting the canonical schema to fit a vendor constraint.

Use application-owned transcription and Model Gateway interfaces. Mock adapters return deterministic fixtures without credentials. Live adapters use OpenAI audio transcription and the Responses API with strict JSON Schema output, `store: false`, no tools, low-detail private frame inputs, and configuration-selected model IDs. Provider calls have bounded retries for transient transport and rate-limit failures; schema violations fail immediately.

Raw transcript text is private analysis input. It is stored under tenant RLS for resumability but is not returned by creative status, deconstruction APIs, or the UI. The Creative DNA prompt treats source material as untrusted delimited data, separates observed evidence from inference, and prohibits performance claims not established by supplied evidence.

## Rationale

- One ledger-backed analysis job gives the user one observable, replay-safe transition from media preprocessing to a ready deconstruction.
- A transcript lineage run satisfies the global artifact-lineage invariant and makes provider, model, schema, usage, cost, latency, and errors auditable.
- Canonical-schema validation prevents vendor-specific output rules from becoming the product contract.
- Reusing a completed transcript bounds retry cost and avoids duplicate provider work.
- Keeping raw transcript data out of presentation boundaries prepares the mandatory Originality Firewall for Milestone 5 and Composer isolation for Milestone 6.

## Consequences

- Mock mode chains media and analysis jobs inline and reaches `READY`; live mode requires an external worker to claim the same Postgres ledger.
- `gpt-transcribe` and `gpt-5.6-luna` are configurable defaults, not domain constants.
- The application validates full schema semantics before invoking service-only completion functions. Database constraints enforce schema version and tenant relationships but do not duplicate complete JSON Schema evaluation.
- Source-derived text remains available to analysis and the future Skeleton extractor, but Composer must never query or receive it.
- Milestone 5 must create a separate Skeleton artifact and restricted-element boundary; Creative DNA alone is not the Originality Firewall.
