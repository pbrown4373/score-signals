# ADR 0004 — Initial runtime, hosting, and provider portfolio

Status: Accepted

## Decision

Use a Node 24/npm modular Next.js application with the App Router. Deploy the web application to Vercel, use Supabase for Postgres/Auth, Cloudflare R2 for private objects, Trigger.dev for durable jobs, OpenAI behind separate model and transcription adapters, Stripe for billing, Resend for email, and PostHog for product analytics.

Every provider remains behind an application-owned interface with a deterministic mock. Provider SDKs are installed only in the milestone that introduces the corresponding live adapter.

## Rationale

- matches the repository's technology direction,
- keeps the MVP operationally small,
- provides durable asynchronous execution for media and AI work,
- keeps CI and local development independent of paid credentials,
- preserves replacement options without adding microservices.

## Consequences

- preview and production environments need separate provider configuration,
- FFmpeg jobs require a suitable worker runtime rather than a request function,
- vendor-specific capabilities cannot leak into domain types,
- changing a provider should require an adapter change rather than domain rewrites.
