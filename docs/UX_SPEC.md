# SCORE UX Specification

## UX objective

A user must understand the path without training:

**Analyze -> Understand -> Adapt -> Export**

SCORE should feel like an intelligence product, not project-management software.

## Public landing

Headline direction:

**Turn successful creative structures into original ideas for your brand.**

Primary CTA:
**Analyze a Creative**

No required "Book a Demo" CTA.

Show:
- three-step explanation
- example DNA
- Skeleton transformation
- originality architecture
- pricing
- FAQ
- privacy/data note

## First-run onboarding

1. account
2. Brand name/category/description
3. product + offer
4. persona pains/desires/objections
5. voice + proof + prohibited claims
6. CTA: **Analyze your first creative**

Optional fields can be skipped and completed later.

## App navigation

- Command Center
- Analyze
- Library
- Concepts
- Brand Brain
- Signals (feature flag/post-MVP)
- Performance (feature flag/post-MVP)
- Account

## Analyze

Tabs:
- Paste URL
- Upload

After submission show real stages:

`Processing -> Transcribing -> Analyzing -> Building Skeleton`

Do not show fake percentage progress.

## Analysis result

Sections:

### Executive Read
- summary
- why it may work
- evidence limitations

### Hook
- classification
- opening
- mechanism

### Psychology
- desire
- problem
- emotion
- awareness
- objections

### Story
- beat timeline

### Proof

### Production

### Offer/CTA

### Skeleton
Visually distinct.

Explain:

**The Skeleton preserves the persuasive architecture while removing source-specific language and details.**

CTA:
**Create Original Concepts**

## Composer

Inputs:
- Brand
- Product
- Persona
- Objective
- optional Offer
- concept count

Show Skeleton summary.
Never display/pass raw transcript as composition context.

CTA:
**Generate Concepts**

## Concepts

Each card:
- title
- angle
- creative hypothesis
- hooks
- script
- beat map
- shot list
- on-screen text
- CTA
- production notes

Originality:
- Passed
- Regenerating
- Withheld / needs rewrite

Actions:
- Copy
- Regenerate
- Create Brief
- Export

## Brand Brain

Simple CRUD for:
- Brand
- Products
- Personas
- Voice
- Proof
- Restrictions

## Empty states

Every empty state must explain the next useful action.

## Error states

Explain:
- what failed,
- whether retry is possible,
- whether quota was consumed,
- alternate action.

## Accessibility

- keyboard usable
- semantic HTML
- labels
- focus handling
- contrast
- no color-only meaning
- reduced motion support

## Visual tone

- clean
- analytical
- premium
- restrained
- high-information clarity

Avoid:
- neon AI cliché
- fake sci-fi dashboards
- confetti
- excessive gradients
