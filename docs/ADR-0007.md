# ADR 0007 — Ledger-first media jobs and private storage adapters

Status: Accepted

## Decision

Use Postgres as the durable source of truth for media-processing jobs. Create a unique `MEDIA_PROCESSING` job only after uploaded bytes pass size and byte-level MIME validation. Service-only database functions claim, finish, fail, and requeue the job; completion advances the creative to `TRANSCRIBING`, the Milestone 4 handoff state.

Use an application-owned private-storage interface with a filesystem implementation in mock mode and an S3-compatible Cloudflare R2 implementation in live mode. Object keys are tenant/creative scoped, upload targets are short lived, raw objects carry a default 30-day expiration record, and no public object URL is persisted or returned by status APIs.

Mock mode dispatches a durable job inline and runs real FFmpeg deterministically. Live mode leaves the job queued for an external worker to claim. Trigger.dev remains the planned runner, but its SDK is deferred until that worker is deployed; it will orchestrate the existing ledger rather than replace it.

URL intake has an explicit adapter interface and empty-by-default allowlist. Before adapter selection, URLs must use HTTP(S), contain no credentials, avoid local/internal hostnames, and resolve exclusively to public addresses. Unsupported sources direct the user to upload instead of attempting arbitrary scraping.

## Rationale

- Database durability and unique idempotency keys make request retries safe even if a dispatcher or worker is interrupted.
- Keeping orchestration vendor-neutral avoids coupling domain state to a scheduler and gives local/CI the same observable state machine as production.
- Direct-to-object-store uploads avoid routing production-sized media through a constrained web runtime.
- Real FFmpeg over synthetic fixtures verifies the deterministic transform without paid services.
- An empty URL-adapter allowlist meets the no-unauthorized-scraping contract and provides a secure extension point.

## Consequences

- Mock completion waits for FFmpeg so tests can observe a finished preprocessing job immediately; production requests return after enqueueing.
- Live media processing is not operational until a worker deployment claims the ledger and has private-storage plus FFmpeg access.
- Retry reuses the failed job and deterministic derived keys. A successful job is not retryable.
- The original object and derived artifacts remain private; future media display must use short-lived authorized download URLs.
- DNS validation data is supplied to an adapter, which must pin or revalidate connections and enforce redirect, timeout, content-type, and byte limits when an approved URL adapter is implemented.
